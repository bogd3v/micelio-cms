# ASVS verification

How the Micelio CMS measures up against the [OWASP Application Security Verification Standard](https://github.com/OWASP/ASVS/tree/v5.0.0), **version 5.0.0**. This is the reference of every security review, as section 9 of the [engineering standard](../engineering-standard.md) says: level 2 for authentication, sessions, access control and input handling (chapters V1, V2, V6, V7 and V8), level 1 for the rest. The security reviewer ([`.claude/agents/security.md`](../../.claude/agents/security.md)) reports findings against the ids below. The frontend keeps the same mapping for its side in `bogd3v/micelio`, `docs/security/asvs.md`.

The mapping covers every level 1 and level 2 requirement of the 17 chapters, so that a reader can tell what was verified and what was never looked at. Level 3 is out of scope. Requirements are named by id and paraphrased, never quoted: the ASVS text is licensed under CC BY-SA 4.0 and stays at its source.

- **Snapshot:** `bogd3v/micelio-cms` at commit `6fecfa9`, Strapi 5.56.0, read on 2026-10-13. Findings come from reading the code, the configuration, the tests and the installed packages. Rows about Fedify cite 2.4.2, the version in the lockfile; the code paths were read in an install at 2.4.0.
- **Scope:** this repository. Rows that depend on the frontend are mapped in `bogd3v/micelio`; a row points there when the control lives on that side. TLS termination, egress rules, secret storage, log shipping and the reverse proxy belong to the operator.
- **Runs:** the only command run was `npm audit --omit=dev` on 2026-10-13 (V15.2.1). Test suites were not run: a row cites the test that covers it by file and line, or says "No test".
- **Upstream:** Strapi, Fedify and the plugins are dependencies. A row marked Upstream names the package and version and what this repository configures; a configuration here that weakens it makes the row Open.

## How to read it

| Status   | Meaning                                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------ |
| Met      | Enforced here, with the file, document and test that show it. A row may say it is an accepted risk and name the document |
| Upstream | A named dependency guarantees it at the version cited, with the configuration of this repository where it matters        |
| N/A      | Does not apply to a headless CMS API like this one, with the reason                                                      |
| Open     | Not met or not verifiable. The row names the issue (label `security`) that tracks it, or says "Private advisory"         |

An open requirement that an attacker could exploit is **not** described here or in a public issue: it is reported through a private security advisory, as [`SECURITY.md`](../../SECURITY.md) says, and its row says only "Private advisory". Open items that are not exploitable are grouped in five issues:

- #177: Password rules, session lifetime and token audience
- #178: Browser headers, cookies and HTTP details
- #179: Input limits, upload documentation and response fields
- #180: Security logging and log format
- #181: Keys, data classification, outbound traffic and supply chain

## Keeping it true

- A pull request that changes what a row cites (a route, a header, a schema, a permission, a test) updates the row in the same change.
- A security review cites ids from this document and, after it, updates the rows it changed and the totals. A newer ASVS version is adopted in its own pull request that remaps every row.
- A fix for an open row changes its status to Met or Upstream with the evidence, closes the issue and updates the totals.
- A new dependency that handles authentication, files, cryptography or network input gets its rows reviewed in the pull request that adds it.
