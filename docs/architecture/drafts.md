# Drafts

Moved from `CLAUDE.md` (#113). The exception for the core's preview routes was added in #385.

Strapi 5 serves drafts to any caller with `find` when the request carries `?status=draft`, including through populated relations (`/api/categories?populate=articles&status=draft`). `src/utils/drafts-access.ts` (a Document Service middleware registered in `register()`) rejects non-`published` reads on `content-api` routes with 403 unless the caller is a users-permissions user with the `editor` role; API tokens are rejected too, while the admin panel, `/mcp` and server-side code are untouched. The Editor role and its read-only permissions are created by the idempotent `src/migrations/editor-role.ts`. `GET /api/articles/drafts` (editors only: `drafts` permission plus the `global::is-editor` policy, which also rejects API tokens) lists drafts per document and locale that were never published or were edited after publishing, using the admin's "Modified" rule (draft `updatedAt` later than the published one).

**The one exception: the core's preview routes.** `POST /api/micelio/preview/exchange` and `GET /api/micelio/preview/draft` of `@micelio/strapi-plugin-core` are content API routes called with the frontend's API token, and they read a draft through the Document Service (#385). The guard lets a read through when the request's route is one of them, matched by what Strapi keeps in `ctx.state.route`: `info.pluginName` is `micelio` and `handler` is `preview.exchange` or `preview.draft`, never a path prefix (`GRANT_CHECKED_PREVIEW_HANDLERS`). Each checks its own one-use credential before it reads: the exchange trades a preview token (60 s, once, bound to an admin user, a site and a draft), and the draft route serves only the document that a grant names, so an unknown, spent, expired or revoked credential gets `404` before any draft is read (`docs/operate/preview.md` in `micelio-plugin-core`). The API token still needs `plugin::micelio.preview.exchange` or `plugin::micelio.preview.draft` to reach the route, and a route of another plugin or of an `api::` type, even one that names the same handler, keeps the refusal and the `access.draft.refused` line. The order of those reads was checked against `@micelio/strapi-plugin-core` 0.2.0, the pinned version: re-check it on every bump of the core, because a release that reads a draft before its credential check would be unguarded here and no test would see it. `tests/drafts-preview-routes.test.ts` covers both sides.
