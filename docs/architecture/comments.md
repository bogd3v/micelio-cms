# Comments plugin

Moved from `CLAUDE.md` (#113). The fediverse side is in [FEDIVERSE.md](../FEDIVERSE.md); the procedure is the `strapi-comments` skill.

`strapi-plugin-comments` returns pending comments from its public endpoints; `src/middlewares/hide-unapproved-comments.ts` hides them, deciding from the database by comment id (the plugin accepts `omit` and `fields`, so the response can lack `approvalStatus`). Its responses also pass through a fixed zod schema that drops unknown attributes, so `src/middlewares/fediverse-comment-fields.ts` re-attaches `fediverseUri`/`fediverseActorHandle` after the plugin responds. Extend the comments schema through `src/extensions/comments/strapi-server.ts` (a `schema.json` would replace all the plugin's attributes). Most keys in the `comments` block of `config/plugins.ts` are inert. That includes `blockedAuthorProps`, which the public read routes do not apply, so `src/middlewares/strip-comment-author-email.ts` removes `author.email` and `reports` from every successful response of the plugin's public API (a role allowed to read comments would otherwise get every commenter's address and the text of unresolved abuse reports; it also reduces `threadOf` to `{ id }`, the one key the frontend reads; `autopopulate` still asks for both, the moderators' admin views need them). `src/middlewares/restrict-comment-filters.ts` answers 400 to a public request whose `filters` name an author attribute at any depth, and one with a `filters` or `where` key inside `populate`. The same middleware answers 400 to any top-level `fields` parameter: the plugin's response schema needs every attribute, so every list (even `id`, `related` and `content`) made it answer 500 and log the whole zod error at error level; the refusal is one `warn` line without the query values, and the frontend never sends `fields` (`omit` and `fields` inside `populate` still work). Tests: `tests/comments-author-email.test.ts`, `tests/comments-public-fields.test.ts` (the `fields` refusal included).

## Moderator replies federate

A reply an admin writes in the comments view (`isAdminComment`) to a comment that came from the fediverse is sent to that remote thread as a `Note` (`/fediverse/notes/<documentId>`), and retracted when it is removed, blocked or sent back to moderation. The fediverse plugin hooks the comments model's database lifecycle. The note id is in `fediverseNoteUri` (and `fediverseNoteRetracted`), two non-public attributes added in `src/extensions/comments/strapi-server.ts`: the public `fediverseUri` and `fediverseActorHandle` stay `null`, because the frontend marks a comment as remote by either. Only an admin who may moderate comments federates: the comments plugin checks no permission on its admin routes, so the fediverse plugin does. Flow and decisions: [FEDIVERSE.md](../FEDIVERSE.md#5-reply--remote-thread). Test: `tests/fediverse-moderator-replies.test.ts`.

## Reply notifications are off

`strapi-plugin-comments` emails the author of a parent comment when someone replies. A guest's address is never verified, so anyone could make the site send mail to any address, with text of their choice and the super admin's address as sender. `src/extensions/comments/strapi-server.ts` replaces `sendResponseNotification` with a no-op. A notification for registered readers only (confirmed address, approved reply, escaped template, `EMAIL_FROM` as sender) can be added later as its own feature. Test: `tests/comments-api.test.ts`.

## Field rules

The plugin's mapper (`Vm` in `node_modules/strapi-plugin-comments/dist/server/index.js`) moves the author attributes `authorUser`, `authorId`, `authorName`, `authorEmail` and `authorAvatar` into one `author` object. Read rules, as far as this repository checks them:

| Field                                       | Public read routes                                                                                                                                                                                                                                                  | Moderators in the admin panel | Note                                                                                 |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------ |
| `author.email` (`authorEmail`)              | **Never**: removed by `src/middlewares/strip-comment-author-email.ts` (`src/utils/comment-author.ts`), also from the parent of a reply, which is reduced to `{ id }`                                                                                                | Returned                      | Tests: `tests/comments-author-email.test.ts`, `tests/comments-public-fields.test.ts` |
| `reports` (abuse report text and reason)    | **Never**: removed by the same middleware, at every level                                                                                                                                                                                                           | Returned                      | Test: `tests/comments-public-fields.test.ts`                                         |
| `filters`, including inside `populate`      | Rejected with 400 at any depth, including inside `populate` (`src/middlewares/restrict-comment-filters.ts`, keys in `src/constants/comments.ts`)                                                                                                                    | Not this API                  | Test: `tests/comments-public-fields.test.ts`                                         |
| `blockReason` (moderator's text)            | Returned on the comment, not on the `threadOf` of a reply (that is `{ id }`): the moderator writes it to be shown with a blocked comment, so it is public by design (`blockReason` is a field of the frontend's public comment, `docs/security/response-fields.md`) | Returned                      | Test: `tests/response-fields-accounts.test.ts`                                       |
| `author.name`, `author.avatar`, `author.id` | Returned with the comment                                                                                                                                                                                                                                           | Returned                      | Not restricted by this repository                                                    |
| The comment itself (`approvalStatus`)       | Pending and rejected comments are removed, also as the `threadOf` of a visible reply (it becomes `null`; a visible parent is `{ id }`), whatever fields are asked for (`src/middlewares/hide-unapproved-comments.ts`)                                               | Not covered here              | Test: `tests/comments-api.test.ts`                                                   |

- The frontend's token may post (`plugin::comments.client.post`, `src/migrations/api-tokens.ts:31`). `approvalStatus` is set by the server, not taken from the body (ASVS V15.3.3, [asvs.md](../security/asvs.md)).
- `strip-comment-author-email` runs on every successful (status below 300) response of the plugin's public API: bare arrays, single comments, `data`, and nested `children` (`stripPrivateCommentFields`), and reduces every `threadOf` object to `{ id }` (`null` and a bare id stay as they are). Error bodies are not walked.
- Account deletion keeps the comments and clears the link to the reader, the email and the avatar (see [ACCOUNTS.md](../ACCOUNTS.md)).
- The data level of each field is in [data.md](../security/data.md). The per-route field list of the plugin was not traced beyond these rows.
