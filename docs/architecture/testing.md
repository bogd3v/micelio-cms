# Testing

Moved from `CLAUDE.md` (#113); the text is unchanged.

**Testing** (`tests/`) boots a real Strapi instance per suite (`tests/strapi.ts`) against an isolated SQLite file per Jest worker (`.tmp/test-<worker>.db`; `DATABASE_FILENAME` must stay relative to the project root), not mocks — `setupStrapi()`/`cleanupStrapi()` in `beforeAll`/`afterAll` (`cleanupStrapi()` waits for the connection pool to go quiet before destroying it: a successful write leaves queued work, and destroying the pool under it is an unhandled `Error: aborted` that kills Jest before it prints a summary, which is what a test expecting a rejected write hits when the write succeeds). Suites are TypeScript under `strict`: Jest only transpiles them (`tests/helpers/esbuild-transformer.js`, which also converts the ESM-only packages listed in `jest.config.js`, such as Fedify's `structured-field-values`), and `npm run typecheck` checks them through `tests/tsconfig.json`. Jest globals are imported from `@jest/globals`; response shapes live in `tests/helpers/api-types.ts`; inputs that are invalid on purpose carry `// @ts-expect-error` with the reason. Set env vars a suite needs in `beforeAll`, before `setupStrapi()`: imports are hoisted above top-level statements. Fediverse tests force `FEDIVERSE_ENABLED=true` before Strapi boots since env vars are read at plugin-registration time, and run against `tests/helpers/remote-actor.ts`, a fake remote server that serves a signed actor and records what the plugin delivers to its inbox (`allowPrivateAddress` is enabled only when `NODE_ENV=test`). `tests/jest.global-setup.js` compiles the sources into `dist/` once per run and every suite boots from that output: compiling in each suite made parallel workers overwrite each other's files. `npm test` runs the workers in parallel; `npm run test:handles` adds `--detectOpenHandles`, which forces a serial run, to find leaked handles. Run `npm run build:fediverse` first when using `npx jest` directly — the `pretest` hook only runs with `npm test`.

The exact keys of every response the frontend reads from the content API are in `src/constants/response-fields/`, rendered in `docs/security/response-fields.md` (ASVS V15.3.1). The `tests/response-fields-*.test.ts` suites seed one fully populated record per content type and fail when a response carries a key that is not listed there, or lacks a required one. After changing the constants, regenerate the document with `npm run docs:response-fields` (it runs `UPDATE_RESPONSE_FIELDS_DOC=1 npx jest tests/response-fields-docs.test.ts`); the docs test fails until you do. `tests/data-classification.test.ts` checks `src/constants/data-classification.ts` against the schemas Strapi loads and against `docs/security/data.md` (ASVS V14.2.4): every attribute of a classified type has a level, every Restricted one is private or token-only, and every Restricted or Personal one is named in the document. `tests/frontend-queries.test.ts` compares the frontend's populate constants, copied into `tests/helpers/frontend-queries.ts`, with a micelio checkout at `../micelio` and is skipped when there is none.
