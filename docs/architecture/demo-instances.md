# Demo instance and new instances

Moved from `CLAUDE.md` (#113); the text is unchanged.

`compose.demo.yml` runs Postgres, this CMS and the micelio frontend from GHCR images (README, "Run your own site"). An `init` service generates the secrets once into a volume (`scripts/demo-secrets.js`); the frontend shares the CMS's network namespace so its server and the browser both use `http://localhost:1337`, and its distroless image loads the token with an inline Node loader. `MICELIO_DEMO` accepts `true`, `static` and `landing` (any other value disables it): `true` and `static` make `src/migrations/demo-seed.ts` write a neutral bilingual site once (content in `src/migrations/demo/content.ts`, covers generated as SVG; store marker, and never on an instance with articles); `landing` also sets the localized `site-setting.homePage` to the showcase page in each language (#84). `scripts/demo-secrets.js` generates `cms.env`, `frontend.env`, `build.env` and `db_password`, creating each file only when missing and upgrading old volumes without rotating keys; it stops if an existing `cms.env` lacks `FRONTEND_API_TOKEN` or `DATABASE_PASSWORD`. `FRONTEND_API_TOKEN` and `BUILD_API_TOKEN` make `src/migrations/api-tokens.ts` create or update the `frontend` and the read-only `build` Custom API tokens with those keys and their permissions (the frontend's match micelio's `docs/security.md`; the model is in `docs/API_TOKENS.md`). `compose.static.yml` and `compose.landing.yml` (#90, own projects `micelio-demo-static` and `micelio-demo-landing`, identical but for `MICELIO_DEMO` and `NUXT_PUBLIC_SITE_MODE`) extend `init`, `db` and `cms` from the demo compose with `MICELIO_DEMO=static`, a `build` service (micelio-builder `generate`, `network_mode: service:cms`, only `build.env` mounted through a volume `subpath`) writing to the `demo-site` volume, and a `site` service (`serve`) on `127.0.0.1:3000`; `demo/{static,landing}.env.example` hold the image and newsletter variables. `consolidateCategories` only runs on an instance that already has one of BogDev's categories, so new instances get none of them; tests that need them call `tests/helpers/bogdev-categories.ts`.
