# Pages

Moved from `CLAUDE.md` (#113); the text is unchanged.

`api::page.page` (i18n, draft and publish) builds landing pages from the section catalog of micelio's ADR 0005 §11 and ADR 0006: `sections` is a dynamic zone of the 14 `section.*` components in `src/components/section/` (plus their item parts and `section.link`) and `shared.rich-text`, the Markdown block that articles use (#445): it has no `tone` or `align`, and a page stores it but the frontend does not render it until the `micelio` pull request of #445. Fields are semantic; `variant` is an enum of the core's variants, and `tone` (`default`, `raised`, `accent`) and `align` (`start`, `center`) are enums of the options vocabulary of micelio's ADR-0018 section 1, on every `section.*` component, with the vocabulary's defaults (optional, no migration: Strapi sets the default when a section is written, so a section stored before #442 reads `null` until it is saved again, and the frontend treats a missing value as the vocabulary's default; `tests/section-options.test.ts` checks the schemas). The responses carry them as `surplus` in `src/constants/response-fields/pages.ts` until the frontend reads them. Drafts may be incomplete: required fields, item counts (`min`/`max`) and link formats apply on publish. `src/utils/page-sections.ts` (Document Service middleware) adds what the schema can't: a `post-list` with both a category and a tag, and a `scene` model that is not `.glb`/`.gltf`. Item components need their own `collectionName` when a section has the same name in plural (`testimonial` vs `testimonials`). `homePage` of the default site is localized: each language points at its own version of the page. Only API tokens read pages (`src/migrations/page-permissions.ts` removes role permissions). `src/utils/rebuild-hook.ts` calls `REBUILD_HOOK_URL` (debounced, with retries, never failing the publish) on publish, unpublish and delete of articles and pages and on every save of the site, the About page or a category, through `strapi.eventHub`; registered in `bootstrap()` and removed in `destroy()`.

**Site scope (#373).** A page belongs to a site (ADR-0017, section 4), so the core can show the Preview button and answer Strapi's "Open preview" for it (`docs/operate/preview.md` of `@micelio/strapi-plugin-core`). The schema is `src/api/page/content-types/page/schema.ts`, not `schema.json`: Strapi reads a content type of `src/api` from the folder's file named `schema` and ignores an `index.ts` beside it, so the attributes go through `withSiteScope` in code. The five routes carry `SITE_SCOPE_MIDDLEWARE`: `/api/pages` serves the pages of the request's site (the host, or `?site=<slug>`; neither names one, so the default site answers and the frontend sends nothing new), and a slug no site has answers `404` `unknownSite`. The relation is not populated by default and the public role cannot read sites, so the response does not change (`docs/security/response-fields.md`). A page created in the admin takes the site the editor picks; one created outside a request (`demo-seed`, a test) passes `defaultSiteRelation` (`src/utils/default-site.ts`), and the core refuses one with no site. Three boot migrations: `src/migrations/page-site.ts` gives the default site to every row with none (before anything reads pages through the content API), `src/migrations/admin-page-site.ts` lets the admin roles Editor and Author read sites and send the `site` of a page, and `src/migrations/admin-page-settings.ts`, right after it, gives the same roles the page settings ("Page settings (#414)" below). Drafts stay closed to the content API (`docs/architecture/drafts.md`); "Preview drafts on the frontend" is for the Super Admin until a role is given it.

**Block and item ids (#440).** Every block of `page.sections` and `article.blocks` has an optional string `blockId`, and every repeatable item an `itemId` (`id` is Strapi's own; the lists of components are in `src/migrations/block-ids.ts`). The ids are opaque and stay with the content when it is reordered. `fillBlockIds` runs on every boot (`bootstrap()`, after `migrateSliderItems`), writes the component rows directly, so drafts and published versions of pages, articles and the About page are all reached and nothing is republished, and never rewrites an id it finds, so a second run changes nothing. A draft and its published version get different ids until the next publish copies the draft's. The fields are optional here (a client that does not send one keeps working); the generation on save is in `@micelio/strapi-plugin-core`, and the frontend keys by them in micelio. The responses carry the fields as `surplus` in `src/constants/response-fields/` until the frontend reads them. `tests/block-ids-migration.test.ts` covers the migration.

**Eyebrow and anchor (#441).** The twelve sections whose renderer uses `SectionHead` (`section.cta`, `section.faq`, `section.feature-grid`, `section.gallery`, `section.hero`, `section.logo-cloud`, `section.newsletter`, `section.post-list`, `section.pricing`, `section.scene`, `section.stats`, `section.testimonials`) have two optional string fields, `eyebrow` (a short line above the title) and `anchor` (the explicit id a link or a table of contents points at, never derived from the title). Both are optional, so a MINOR of the block contract and no migration: a section without them returns both as `null`, and the frontend treats that as absent. The responses carry them as `surplus` in `src/constants/response-fields/pages.ts` until the frontend reads them. The check that `anchor` is a kebab-case slug, unique in the page, is in `@micelio/strapi-plugin-core`, not here.

**Newsletter consent (#443).** `section.newsletter` has three optional fields: `consentText` (text, no default), `successMessage` and `placeholder` (strings). A consent text is a node's own legal wording (Ley 1581, GDPR), so no code or migration supplies one; an empty `successMessage` or `placeholder` leaves the frontend's own strings in use. They are optional, so a MINOR of the block contract. The boot migration `src/migrations/newsletter-consent.ts` (`reportNewsletterConsent`) writes nothing: it logs one `[newsletter]` warning per stored entry, drafts and published versions, whose `consentText` is empty, and a second boot reports the same entries. The responses carry the three fields as `surplus` in `src/constants/response-fields/pages.ts` until the frontend reads them. The newsletter endpoint's validation and rate limit are unchanged.

**FAQ default open (#447).** `section.faq-item` has an optional boolean `defaultOpen`, default `false`: an item opens already open only when the editor sets it. It is optional with a default, so a MINOR of the block contract and no migration: an item stored before the upgrade returns `null` until an editor saves it again (Strapi applies a default when an entry is saved, not when it is read), and the frontend treats `null` as `false`. The responses carry it as `surplus` in `src/constants/response-fields/pages.ts` until the frontend reads it. `tests/section-options.test.ts` covers the schema.

**Testimonial source, logo and rating (#451).** `section.testimonial` has three optional fields: `sourceUrl` (an `http` or `https` URL, the page the quotation comes from), `logo` (one image, the company's) and `rating` (an integer from 1 to 5). All are optional with no default, so a MINOR of the block contract and no migration: a testimonial stored before the upgrade returns `null` for each, and the frontend treats that as absent. The schema's `max` refuses a `rating` above 5 on every save, while `min` (below 1) and the `sourceUrl` format are checked on publish only, so a draft, and the preview that reads it, can hold a rating of 0 or a URL that is not `http` or `https`, which a consumer must ignore; the plugin core's check of its block entry is in `@micelio/strapi-plugin-core`. The responses carry `sourceUrl` and `rating` as `surplus` in `src/constants/response-fields/pages.ts` until the frontend reads them; `logo` is a media field that the response returns only when the query populates it, and the frontend's `PAGE_POPULATE` (micelio) populates `avatar` only, so `logo` is not in the shape until the `micelio` pull request of #451 adds it to that query (it then lists `logo` as `media-page`). `tests/section-options.test.ts` covers the schema and `tests/testimonial-fields.test.ts` what Strapi refuses on save and on publish.

**Page settings (#414).** The page schema also goes through `withPageSettings` of `@micelio/strapi-plugin-core`, inside `withSiteScope` (`src/api/page/content-types/page/schema.ts`). It adds `pageType` (a string, default `standard`; the core's types are `landing`, `standard` and `long-read`, and a site's budgets may name more), `visibility` (the component `micelio-page.visibility`: `inMenu`, `inSitemap`, `noindex`), the template record `templateId` and `templateVersion`, and the private JSON lists `templateSamples` and `templateFixed`; none is localised, so every language of a page has the same values (`docs/guide/pages.md` of the core). The editor sets the type and the visibility in the builder's **Page settings** drawer (the gear next to the page title); the gallery and the Template tab write the template record. A fresh install's admin roles Editor and Author list `pageType` and the leaves of `visibility` (`visibility.inMenu`, `visibility.inSitemap`, `visibility.noindex`) in their page permissions; the template record and the two private lists are hidden (`visible: false`), so Strapi lists them in no role. On an instance that upgrades the roles lack them (Strapi lists in a role the fields that exist when it creates the role, as the remarks of `grantEditorsPageSite` in `src/migrations/admin-page-site.ts` say), so the boot migration `src/migrations/admin-page-settings.ts` (#517) adds them to the page permissions of Editor and Author that list fields and none of the page settings; it derives them from the page's schema with Strapi's own `getNestedFields`, kept to the attributes `withPageSettings` adds, and leaves a permission an admin narrowed, a role with another name and a custom role as they are (`docs/operate/upgrade.md`, "Upgrading to 0.9"). No boot migration fills them: a page stored before keeps an empty `pageType`, which the core reads as `standard`, and no `visibility`, which reads as in the menu, in the sitemap and indexable. The page routes return `pageType`, `visibility` (when populated), `templateId` and `templateVersion` as `surplus` in `src/constants/response-fields/pages.ts` until the frontend reads them; `templateSamples` and `templateFixed` are private and never returned. The helper also turns on the JSON-LD check of the core's `seoDocuments` middleware: a create or update of a page whose `seo.structuredData` is not a JSON-LD object (with `@context` and `@type`) or a list of them is refused with `400` `structuredDataInvalid`; an empty value is accepted, and a stored page is served as it is. When the page names no `metaTitle` or `metaDescription`, the same middleware derives them from the title and the first paragraph, and leaves the description out when no paragraph is long enough. `withEditorial` is not applied (decision D7 of #360), so a change of a published slug writes no 301 redirect and no weight budget is checked at publish. `tests/page-settings.test.ts` covers the settings and `tests/admin-page-settings.test.ts` the migration.

**Post list: featured, sort and excerpt (#444).** `section.post-list` has two optional fields, `showExcerpt` (boolean, default `true`, so a list keeps its description) and `sort` (`newest`, `oldest`, `alphabetical`; default `newest`), and its `variant` enum gains `featured` (the first entry larger). They are optional with defaults, so a MINOR of the block contract and no migration: a list stored before the upgrade returns `null` for both until an editor saves it again, and the frontend treats `null` as the default. The responses carry them as `surplus` in `src/constants/response-fields/pages.ts` until the frontend reads them. `tests/section-options.test.ts` covers the schema.
