# Pages

Moved from `CLAUDE.md` (#113); the text is unchanged.

`api::page.page` (i18n, draft and publish) builds landing pages from the section catalog of micelio's ADR 0005 §11 and ADR 0006: `sections` is a dynamic zone of the 14 `section.*` components in `src/components/section/` (plus their item parts and `section.link`). Fields are semantic; `variant` is an enum of the core's variants, the only visual choice. Drafts may be incomplete: required fields, item counts (`min`/`max`) and link formats apply on publish. `src/utils/page-sections.ts` (Document Service middleware) adds what the schema can't: a `post-list` with both a category and a tag, and a `scene` model that is not `.glb`/`.gltf`. Item components need their own `collectionName` when a section has the same name in plural (`testimonial` vs `testimonials`). `site-setting.homePage` is localized: each language points at its own version of the page. Only API tokens read pages (`src/migrations/page-permissions.ts` removes role permissions). `src/utils/rebuild-hook.ts` calls `REBUILD_HOOK_URL` (debounced, with retries, never failing the publish) on publish, unpublish and delete of articles and pages and on every save of the site settings, the About page or a category, through `strapi.eventHub`; registered in `bootstrap()` and removed in `destroy()`.

**Site scope (#373).** A page belongs to a site (ADR-0017, section 4), so the core can show the Preview button and answer Strapi's "Open preview" for it (`docs/operate/preview.md` of `@micelio/strapi-plugin-core`). The schema is `src/api/page/content-types/page/schema.ts`, not `schema.json`: Strapi reads a content type of `src/api` from the folder's file named `schema` and ignores an `index.ts` beside it, so the attributes go through `withSiteScope` in code. The five routes carry `SITE_SCOPE_MIDDLEWARE`: `/api/pages` serves the pages of the request's site (the host, or `?site=<slug>`; neither names one, so the default site answers and the frontend sends nothing new), and a slug no site has answers `404` `unknownSite`. The relation is not populated by default and the public role cannot read sites, so the response does not change (`docs/security/response-fields.md`). A page created in the admin takes the site the editor picks; one created outside a request (`demo-seed`, a test) passes `defaultSiteRelation` (`src/utils/default-site.ts`), and the core refuses one with no site. Two boot migrations: `src/migrations/page-site.ts` gives the default site to every row with none (before anything reads pages through the content API) and `src/migrations/admin-page-site.ts` lets the admin roles Editor and Author read sites and send the `site` of a page. Drafts stay closed to the content API (`docs/architecture/drafts.md`); "Preview drafts on the frontend" is for the Super Admin until a role is given it.
